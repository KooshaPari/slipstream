## Cause

`detect_active_session()` in `crates/ss-vdisplay/src/display/session.rs` referenced `WRAPPED_COMMS` at line 374. The constant had been declared **inside** `is_kwin_compositor_comm()`, so it was out of scope in the caller. CI reported:

```text
error[E0425]: cannot find value `WRAPPED_COMMS` in this scope
   --> crates/ss-vdisplay/src/display/session.rs:374:32
374 |             let kwin_cmdline = WRAPPED_COMMS
    |                                ^^^^^^^^^^^^^ not found in this scope
```

The constant list was not duplicated elsewhere in the crate: `git grep -n "WRAPPED_COMMS" -- .` found only the declaration and the failing use.

## Fix

- Promoted the wrapped-KWin `comm` list to module scope as `WRAPPED_KWIN_COMMS`, with `#[cfg(target_os = "linux")]` to match the helper and caller.
- Updated `detect_active_session()` to use `WRAPPED_KWIN_COMMS`.
- Kept the existing positive cases for `kwin_wayland`, `.kwin_wayland-w`, `.kwin_wayland_w`, and `.kwin_wayland-wrapped`, and the argv0 checks for `kwin_wayland`, `kwin_wayland_wrapper`, and `kwin_wayland-wrapped`.
- Kept all negative unit-test assertions unchanged, including rejection of `.kwin_wayland-wrong`, `kwin_wayland` with the wrong `comm`, `not_kwin_wayland`, `kwin_wayland_x`, `.kwin_wayland_x`, and empty `comm`.

Files changed: `crates/ss-vdisplay/src/display/session.rs`, this report.
