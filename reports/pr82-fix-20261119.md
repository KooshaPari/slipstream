## Cause

`detect_active_session()` in `crates/ss-vdisplay/src/display/session.rs` referenced `WRAPPED_COMMS`, but the constant was declared inside `is_kwin_compositor_comm()`, so it was out of scope in the caller. CI reported:

```text
error[E0425]: cannot find value `WRAPPED_COMMS` in this scope
   --> crates/ss-vdisplay/src/display/session.rs:374:32
374 |             let kwin_cmdline = WRAPPED_COMMS
    |                                ^^^^^^^^^^^^^ not found in this scope
```

`git grep -n "WRAPPED_COMMS" -- .` found only that declaration and use, so there was no existing crate-level constant to import.

## Fix (maintainer's literal instructions)

- Hoisted the original `WRAPPED_COMMS` name to module scope under `#[cfg(target_os = "linux")]`; it contains the two wrapped KWin `comm` names that fit Linux's 15-character limit:
  - `.kwin_wayland-w` (15 chars)
  - `.kwin_wayland_w` (15 chars)
- Removed the impossible `.kwin_wayland-wrapped` comm arm and its test assertions. That name is 21 characters and can never appear in a 15-character `comm` field.
- Removed the dead `.kwin_wayland-wrapped` entry from the hoisted constant.
- Kept long wrapper detection on the untruncated argv0/cmdline path. Surviving comm arms are:
  - `kwin_wayland` (12 chars) accepts native argv0 without further checks.
  - `.kwin_wayland-w` (15 chars) accepts argv0 `kwin_wayland` or `kwin_wayland_wrapper`.
  - `.kwin_wayland_w` (15 chars) accepts argv0 `kwin_wayland_wrapper`.
- Documented that the 20-character `kwin_wayland_wrapper` name cannot appear in `comm`; no truncated-prefix hack was added.
- Preserved negative assertions for `.kwin_wayland-wrong`, `.kwin_wayland-w` with no cmdline, `.kwin_wayland_w` with the wrong argv0, and non-KWin/similar comm names.
